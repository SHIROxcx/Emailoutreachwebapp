Outlook Outreach Scheduler

Full-stack automated cold email scheduling system with Microsoft Graph integration, multi-touch sequences, Spintax permutation engine, strict safety guardrails, and autonomous BullMQ queue execution.

Executive Summary

The Outlook Outreach Scheduler is an enterprise-grade cold email orchestration web platform engineered specifically for Microsoft 365 and personal Outlook mailboxes. It solves the critical deliverability challenges inherent in outbound email marketing: preventing spam flags, respecting strict Graph API rate limits, protecting sender domain reputation, eliminating human configuration error through pre-flight audits, and honoring CAN-SPAM and GDPR compliance.

Autonomy

Autonomous BullMQ worker daemon running 24/7 on Redis, executing scheduled staggered dispatch ticks every 5 minutes with midnight quota resets.

Deliverability

Spintax permutation trees (`{Hi|Hello}`), dynamic merge tags (`{{firstName}}`), business-hours delivery windows (Mon–Fri 9–5), and custom delay stagger.

Safety Guardrails

Automated circuit breaker that auto-pauses on 3 consecutive errors, pre-flight launch verification modal, opt-out suppression, and 1-click Emergency Stop.

Core Engine & Feature Implementation

1. Lead Directory & Smart CSV Column Mapping

Uploaded prospect files are parsed with papaparse. A column-mapping dialog allows users to map any CSV column structure to required fields: email, firstName, lastName, and company. Leads are deduplicated on (tenantId, email) at the database level.

  • B2B Demo Generator: One-click generation of 12 realistic prospect leads across tech and SaaS to immediately test sequences.
  • Row-Level Quick Actions: Quick Test Send pre-filling modal with that lead's data, one-click email copying, and individual lead deletion.
  • Bulk Actions Toolbar: Multi-select leads with floating toolbar to bulk-enroll into campaigns, export to CSV, or batch-delete.

2. Sequence Studio & Spintax Variation Engine

Campaign sequences support multi-step follow-ups with configurable delays (e.g. Step 1: Day 0, Step 2: Day 2, Step 3: Day 5).

  • Spintax Permutation Parser (src/lib/template-engine.ts): Evaluates variations such as {Quick question|Reaching out|Hello}. Supports nested syntax trees.
  • Dynamic Variables with Fallbacks: Resolves merge fields like {{firstName | "there"}}, {{company | "your team"}}, and {{email}}. Double braces are resolved before spintax pipes to prevent variable collision.
  • Live Preview Modal: Live preview tool allowing users to pick enrolled prospect records, test random variation generation, and click "Re-Spin" to preview permutation diversity.

3. Core Dispatcher & BullMQ Background Queue

The sending dispatcher (src/lib/worker/dispatcher.ts) processes active sequence enrollments:

  • Token Lifecycle: Pre-flight check evaluates whether OAuth token expires within 2 minutes. If expired, automatically calls msalClient.acquireTokenByRefreshToken(), re-encrypts the new token with AES-256-GCM, and updates PostgreSQL.
  • Step Transitioning: Dispatches current step, schedules nextSendAt = now + delayDays * 86400000 for the subsequent step, or transitions status to completed.
  • BullMQ Daemon (scripts/run-worker.ts): Runs via npm run worker. Listens for the 5-minute tick and midnight quota reset without requiring user clicks.

4. Multi-Layer Campaign Safety Guardrails

To eliminate account suspension risks and deliverability damage:

Pre-Flight Launch Verification Modal

Intercepts activation clicks to audit mailbox health, sequence readiness, audience protection, and schedule alignment. Requires explicit user confirmation.

Sending Windows & Days

Enforces delivery only during business hours (e.g. Mon–Fri 09:00–17:00). If outside the window, sends are deferred to the next window opening rather than failing.

Dual Safe Quotas

Mailbox ceiling (default 50/day) and Campaign limit (default 30/day) enforced before each send to safeguard warm-up health.

Circuit Breaker & Emergency Stop

Auto-pauses campaign on 3 consecutive errors (e.g. Graph 429 rate limit). 1-click Emergency Stop halts all sending immediately.

5. Live Activity Feed & Email Inspector

Dispatched emails are recorded in real-time in the dashboard Activity Feed with status badges (sent, simulated, failed). Users can filter by tabs (All, Test Sends, Campaigns) and click any row to open the full email inspector modal showing recipient, exact subject, timestamp, and body preview.

Step-by-Step User Manual

Step 1: Connecting Outlook or Using Demo Mode

1. Open http://localhost:3000 in your browser.

2. Choose "Sign in with Microsoft" to connect your real Outlook account via Microsoft Entra ID (delegated permissions: Mail.Send, User.Read, offline_access).

3. Or choose "Use Demo Account" to launch an instant local simulation session with zero configuration.

Step 2: Managing Prospects in Leads Directory

1. Navigate to Leads from the top navigation.

2. Click "Upload CSV" to upload a prospect list and map columns, or click "Generate Demo Leads" to populate 12 sample B2B contacts.

3. Use checkboxes to select leads and open the floating bulk toolbar to enroll them in campaigns or export to CSV.

Step 3: Creating Campaigns & Writing Sequences

1. Navigate to Campaigns and click "New Campaign".

2. In the Sequences tab, write your subject and body template. Use merge tags: {{firstName}}, {{company}}, or fallbacks like {{firstName | "there"}}.

3. Add Spintax variation blocks: {Quick question|Reaching out|Checking in}.

4. Click "Preview & Test" to open the spintax simulation tool and verify personalized output.

5. Click "+ Add Follow-up Step" to create subsequent steps and configure the delay (e.g. 2 days).

6. Switch to the Leads tab and click "Enroll Leads" to assign your prospect batch.

Step 4: Configuring Safety Guardrails

1. In Campaign Studio, switch to the Settings & Guardrails tab.

2. Adjust the Daily Campaign Sending Limit slider (recommended: 20–30 emails/day).

3. Set your Business Hours Sending Window (e.g. 09:00 to 17:00) and pick your allowed active sending days (Mon–Fri).

4. Configure the Minimum Dispatch Stagger (e.g. 60 seconds) and Circuit Breaker Threshold (e.g. 3 errors).

5. Click "Save Campaign & Safety Settings".

Step 5: Activating Campaigns & Running Dispatches

1. Click "Draft / Paused (Activate)" in the campaign header.

2. The Pre-Flight Verification Modal will pop up and run live audits on mailbox health, sequence steps, audience count, and delivery windows.

3. Review any warnings, toggle Dry Run mode if you want a simulated run, and click "Confirm & Arm Campaign".

4. To run an immediate send pass, click "Run Dispatch Pass".

5. If you ever need to stop all sending immediately, click the red "Emergency Stop" button in the Campaigns header.

Prisma Database Domain Model

model Tenant {
  id        String      @id @default(cuid())
  name      String
  createdAt DateTime    @default(now())
  users     User[]
  leads     Lead[]
  campaigns Campaign[]
}

model User {
  id                 String              @id @default(cuid())
  tenantId           String
  email              String              @unique
  createdAt          DateTime            @default(now())
  tenant             Tenant              @relation(fields: [tenantId], references: [id])
  mailboxConnections MailboxConnection[]
}

model MailboxConnection {
  id                    String     @id @default(cuid())
  userId                String
  msAccountEmail        String
  accessTokenEncrypted  String
  refreshTokenEncrypted String
  tokenExpiresAt        DateTime
  dailySendCount        Int        @default(0)
  dailySendResetAt      DateTime   @default(now())
  dailyLimit            Int        @default(50) // Mailbox safe cap
  status                String     @default("connected") // connected | expired | revoked
  user                  User       @relation(fields: [userId], references: [id])
  campaigns             Campaign[]
}

model Lead {
  id            String               @id @default(cuid())
  tenantId      String
  email         String
  firstName     String?
  lastName      String?
  company       String?
  customFields  Json?
  status        String               @default("active") // active | unsubscribed | bounced
  importBatchId String?
  createdAt     DateTime             @default(now())
  tenant        Tenant               @relation(fields: [tenantId], references: [id])
  enrollments   SequenceEnrollment[]

  @@unique([tenantId, email])
}

model Campaign {
  id                   String               @id @default(cuid())
  tenantId             String
  name                 String
  mailboxConnectionId  String
  status               String               @default("draft") // draft | active | paused | done
  
  // Delivery & Safety Guardrails
  dailyLimit           Int                  @default(30)
  sendingWindowStart   String               @default("09:00")
  sendingWindowEnd     String               @default("17:00")
  sendingDays          String               @default("1,2,3,4,5") // Mon-Fri
  minIntervalSeconds   Int                  @default(60)
  maxConsecutiveErrors Int                  @default(3) // Circuit breaker
  dryRunMode           Boolean              @default(false)
  safetyPausedReason   String?

  tenant              Tenant               @relation(fields: [tenantId], references: [id])
  mailboxConnection   MailboxConnection    @relation(fields: [mailboxConnectionId], references: [id])
  sequence            Sequence?
  enrollments         SequenceEnrollment[]
}

model Sequence {
  id         String         @id @default(cuid())
  campaignId String         @unique
  campaign   Campaign       @relation(fields: [campaignId], references: [id])
  steps      SequenceStep[]
}

model SequenceStep {
  id              String   @id @default(cuid())
  sequenceId      String
  stepOrder       Int
  delayDays       Int
  subjectTemplate String
  bodyTemplate    String
  sequence        Sequence @relation(fields: [sequenceId], references: [id])
}

model SequenceEnrollment {
  id            String    @id @default(cuid())
  leadId        String
  sequenceId    String
  campaignId    String
  currentStepId String?
  nextSendAt    DateTime
  status        String    @default("active") // active | paused | completed | bounced
  retryCount    Int       @default(0)
  nextRetryAt   DateTime?
  lead          Lead      @relation(fields: [leadId], references: [id])
  campaign      Campaign  @relation(fields: [campaignId], references: [id])
}

model SendLog {
  id             String   @id @default(cuid())
  enrollmentId   String?
  stepId         String?
  recipientEmail String
  subject        String
  bodyPreview    String?  @db.Text
  campaignName   String?
  isTest         Boolean  @default(false)
  sentAt         DateTime @default(now())
  graphMessageId String?
  status         String   // sent | failed | simulated | retried
  errorMessage   String?
}
