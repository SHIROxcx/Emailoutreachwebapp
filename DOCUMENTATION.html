Outlook Outreach Scheduler

Enterprise cold outbound email automation system engineered for Microsoft 365 and personal Outlook mailboxes, featuring recursive Spintax permutations, multi-layer delivery safety guardrails, and autonomous BullMQ queue execution.

Core Architectural Objective

Cold email deliverability is fragile. The Outreach Scheduler is engineered under a zero-accident standard: every sequence is evaluated by pre-flight runtime audits, bounded by dual daily quotas, restricted to recipient business hours, and monitored by an automated circuit breaker that pauses execution upon consecutive delivery errors.

Outbound Delivery Pipeline

Every enrolled prospect advances through 5 discrete stages before email dispatch:

Step 1
Prospect Enrolled
CSV import or generated demo lead with verified metadata
Step 2
Sequence Rendered
Recursive Spintax permutation and fallback variable merge
Step 3
Pre-Flight Audit
6-point runtime safety verification prior to arming
Step 4
BullMQ Scheduled
Enqueued in Redis with configurable delay staggers
Step 5
Microsoft Graph
Direct dispatch via Outlook OAuth 2.0 PKCE token vault

Phase 02 Authentication Delivered

Microsoft Graph Integration & OAuth 2.0 Token Vault

Systems Constraint

Basic authentication is deprecated across Microsoft Exchange and Outlook. Storing plain-text credentials introduces unacceptable security vulnerabilities.

Architectural Solution

Integrated Microsoft Authentication Library (MSAL) utilizing OAuth 2.0 PKCE. Configured encrypted AES-256 token persistence in PostgreSQL with automatic background refresh.

Phase 04 Sequence Studio Delivered

Campaign Studio, Spintax Permutations & Cascade Deletion

Systems Constraint

Campaign deletion previously caused foreign-key deadlock errors in PostgreSQL. Furthermore, outbound templates with identical content across prospects trigger anti-spam heuristics.

Architectural Solution

Resolved relational cascade deletion via atomic transactions. Engineered a recursive Spintax parser supporting nested brackets and fallback merge tags, paired with an interactive Spintax Preview modal.

Recursive Spintax permutation engine:

export function parseSpintax(text: string): string {
  const pattern = /\{([^{}]+)\}/g;
  while (pattern.test(text)) {
    text = text.replace(pattern, (_, choices) => {
      const options = choices.split('|');
      return options[Math.floor(Math.random() * options.length)];
    });
  }
  return text;
}

Phase 06 Safety Shield Zero-Accident

Multi-Layer Campaign Execution Safety Guardrails

Systems Constraint

Cold outreach carries existential domain risks: sending outside business hours, exceeding rate limits, emailing unsubscribed contacts, or continuing after mailbox errors.

Architectural Solution

Built a 5-layer safety architecture: 6-stage pre-flight verification modal, dual daily quotas, target timezone business hours window, circuit breaker auto-pause, and a global Emergency Stop kill switch.

Initial State
Unchecked activation risked accidental mass dispatches during off-hours or after errors.
Delivered State
Mandatory pre-flight audit checklist, daily quotas, business hours filter, circuit breaker, and 1-click kill switch.

Circuit breaker auto-pause execution:

if (consecutiveFailures >= 3) {
  await prisma.campaign.update({
    where: { id: campaign.id },
    data: {
      status: 'PAUSED',
      pauseReason: 'CIRCUIT_BREAKER_TRIGGERED: 3 consecutive failures',
    },
  });
}
Phase 07 Background Engine Delivered

Autonomous Background Worker (BullMQ + Redis)

Systems Constraint

Outreach cannot rely on keeping browser tabs open. Execution must proceed continuously as an autonomous daemon with graceful error recovery.

Architectural Solution

Implemented BullMQ v6 on Redis 7 with repeatable job schedulers running every 5 minutes (`dispatch-5min-tick`) and daily quota resets at midnight UTC (`0 0 * * *`). Packaged into a standalone daemon process.

BullMQ repeatable scheduler registration:

await outreachQueue.upsertJobScheduler('dispatch-5min-tick', { every: 300000 });
await outreachQueue.upsertJobScheduler('midnight-quota-reset', { pattern: '0 0 * * *' });

// Launch daemon
npm run worker

Safety Guardrails & Compliance

Detailed breakdown of the 5 runtime defenses protecting sender reputation:

Dual Quota Protection
Independent ceilings for mailboxes (50/day) and individual campaigns (30/day), with automated midnight UTC resets.
Business Hours Windows
Strict delivery window restriction (09:00 to 17:00 target timezone, Mon–Fri). Sends are deferred, never dropped.
Circuit Breaker & Kill Switch
Auto-pauses campaign after 3 consecutive delivery failures. Global red Emergency Stop button pauses all active sends in 1 click.

Background Queue & Worker Architecture

The queue system is built on BullMQ v6 and Redis 7, operating entirely decoupled from user browser sessions:

Scheduler Name Cadence Action Executed
dispatch-5min-tick Every 5 minutes (*/5 * * * *) Evaluates active campaigns, checks quotas, checks windows, and sends due sequence steps.
midnight-quota-reset Daily at midnight UTC (0 0 * * *) Resets dailySendCount to 0 across all active mailbox connections.
