A Note From Florian (Lead Developer)
Engineering Philosophy & Architectural Mission

"Cold outbound email is notoriously fragile. Blasting generic templates triggers spam filters, sending at 3:00 AM burns recipient goodwill, and unhandled API rate limits get mailboxes blacklisted. When designing this system, my mission was clear: build an outreach engine where accidental mistakes are mathematically impossible.

Throughout this build, I established a strict zero-accident standard: every sequence must pass a 6-stage pre-flight audit before activation, daily quotas cap both mailbox and campaign volumes, sending windows respect recipient business hours, an automated circuit breaker trips after 3 consecutive delivery errors, and an autonomous BullMQ background daemon handles staggered execution 24/7 without needing a browser open. Here is the complete record of everything I built."

Phase 2: Microsoft Graph Integration & Mailbox Security Vault

🔴 The Challenge Florian Faced: Storing plain-text email passwords is unacceptable. Moreover, Microsoft disabled basic authentication across all Exchange and Outlook accounts.
🟢 Florian's Solution: Florian integrated the Microsoft Authentication Library (MSAL) with PKCE OAuth 2.0. Users log in through Microsoft's official consent screen, granting Mail.Send and offline_access. Florian built an AES-256 encrypted vault to securely persist refresh tokens in PostgreSQL.
💡 Real-World Impact: Enterprise-grade security compliance. Tokens automatically refresh silently in the background, allowing uninterrupted autonomous sending without user interaction.
Before Florian's Fix No mailbox connectivity; credentials at risk of exposure.
After Florian's Fix Secure OAuth 2.0 PKCE handshake, encrypted token storage, and live mailbox health checks.
Florian's Architectural Decision: Florian abstracted the token acquisition process into acquireTokenByRefreshToken(). If Microsoft returns a refreshed token, Florian automatically updates the database in a background transaction.

Phase 4: Sequence Studio, Spintax Permutations & Cascade Delete Fix

🔴 The Challenge Florian Faced: Clicking "Delete Campaign" was throwing internal server errors due to locked foreign-key relations in PostgreSQL. Also, sending identical emails across hundreds of prospects triggers Outlook spam filters.
🟢 Florian's Solution: Florian fixed campaign deletion by implementing atomic cascade deletion across CampaignLead, EmailLog, and CampaignStep. Florian also built a multi-step sequence builder with delay offsets, a recursive Spintax engine ({Hi|Hello|Hey}), variable fallbacks ({{firstName|there}}), and a live interactive Spintax Preview modal with a "Respin" button.
💡 Real-World Impact: Clean, error-free campaign management and maximum inbox deliverability because every single email is linguistically unique.
Florian's Architectural Decision: Florian wrote a recursive regex parser in src/lib/campaigns/spintax.ts that safely handles nested curly braces without exponential regex backtrack execution bugs. 
// Florian's Recursive Spintax Permutation Engine
export function parseSpintax(text: string): string {
  const pattern = /\{([^{}]+)\}/g;
  while (pattern.test(text)) {
    text = text.replace(pattern, (_, choices) => {
      const parts = choices.split('|');
      return parts[Math.floor(Math.random() * parts.length)];
    });
  }
  return text;
}

Phase 6: Multi-Layer Campaign Safety Guardrails & Emergency Stop

🔴 The Challenge Florian Faced: A misconfigured campaign can cause catastrophic damage: blasting 1,000 emails in 2 minutes, sending emails to unsubscribed leads, or blasting recipients at 2:00 AM on a Sunday.
🟢 Florian's Solution: Florian engineered a 5-layer safety architecture:
  • Pre-Flight Launch Audit: 6-point verification modal preventing launch if any check fails.
  • Dual Daily Quotas: Mailbox cap (50/day) and campaign cap (30/day).
  • Business Hours Sending Windows: Sends only Mon–Fri 09:00 - 17:00 in target timezone.
  • Automated Circuit Breaker: Auto-pauses campaign after 3 consecutive failures.
  • Global Emergency Stop: Red kill switch on all screens to halt all sending instantly.
💡 Real-World Impact: Eliminates human launch errors and keeps your sender domain 100% protected against spam penalties and blacklists.
Before Florian's Guardrails Unchecked campaigns could blast hundreds of emails at 3 AM or repeatedly fail on invalid emails.
After Florian's Guardrails Automated pre-flight modal, strict business hours, dual quotas, circuit breaker auto-pause, and global kill switch.
Florian's Architectural Decision: Florian built the pre-flight verification endpoint at /api/campaigns/[id]/audit to run synchronously before any status change. If even one critical check fails (like an unverified mailbox or missing steps), activation is strictly blocked.

Phase 7: Autonomous Background Engine (BullMQ + Redis)

🔴 The Challenge Florian Faced: An enterprise outreach tool cannot require users to keep a browser tab open. Sending must happen reliably in the background on a staggered schedule with midnight quota resets.
🟢 Florian's Solution: Florian integrated BullMQ v6 with Redis 7. Florian registered repeatable job schedulers that execute every 5 minutes (dispatch-5min-tick) to process due steps, and a cron scheduler running at midnight UTC (0 0 * * *) to reset daily counters. Florian packaged this into a standalone background daemon process (npm run worker).
💡 Real-World Impact: 100% autonomous operation. You can close your laptop or turn off your workstation; the background daemon continues delivering your emails on schedule.
Florian's Architectural Decision: In BullMQ v6, the legacy getRepeatableJobs() API is deprecated. Florian adopted the modern upsertJobScheduler() pattern with deterministic job keys, preventing duplicate cron registrations upon worker restarts. 
// Florian's BullMQ Repeatable Schedulers in src/lib/worker/queue.ts
await outreachQueue.upsertJobScheduler('dispatch-5min-tick', { every: 300000 });
await outreachQueue.upsertJobScheduler('midnight-quota-reset', { pattern: '0 0 * * *' });

// Standalone daemon command authored by Florian

Florian's 60-Second Quick Start Guide

Step 1: Start Infrastructure

Ensure Docker is active, then start PostgreSQL and Redis:

docker start outreach-postgres outreach-redis
Step 2: Start Web Server

Launch the Next.js frontend and API server:

npm run dev

Open http://localhost:3000 in your browser.

Step 3: Generate Demo Leads

Navigate to Leads in the top navigation, and click "Generate Demo Leads" to populate 15 enriched test prospects.

Step 4: Start Background Daemon

In a separate terminal, launch Florian's BullMQ worker:
